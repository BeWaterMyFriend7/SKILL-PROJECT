# Code Merge Helper

围绕双方意图和冲突裁决组织报告：哪些行为应保留、哪些可以舍弃、为什么，以及如何验证组合结果。

## 分析流程

1. 确认分析范围、操作类型、双方实际提交、应用基线、索引及已有工作区修改。按 [分析规则](references/analysis-rules.md) 区分提交身份与文件 stage blob。
2. 分析文本冲突及自动合并文件、相关调用方中的语义冲突。合并前评估没有冲突索引时，不假造 stage。
3. 还原双方行为变化及证据；将相互关联的冲突按功能组成裁决单元。
4. 为每个单元选择保留一侧、语义融合或人工决策。明确保留与舍弃的行为、理由和影响；不能为形式上的双侧保留拼接互斥行为。
5. 给出逐项文件/符号解决动作，并按 [验证选择](references/verification-matrix.md) 就地配套验证。仅存在跨冲突依赖时补充解决顺序。
6. 按 [报告模板](assets/merge-resolution-report.md) 形成判断和执行清单；关键证据不足则暂缓，不填造最终裁决。

需要 Git 命令取证时读取 [命令参考](references/git-command-reference.md)。本阶段设计后续验证，不在被分析仓库执行会生成文件或修改状态的解决流程。

## 报告结构

- **人类合并判断与冲突裁决**：合并判断、比较范围与双方身份、按功能组织的冲突裁决。每项解释双方目的、冲突实质、推荐结果及依据；未决问题就地说明。
- **AI 冲突解决清单**：Git 精确依据、按正文裁决标题对应的文件动作和验证、跨冲突依赖与整体检查、停止条件、当前操作适用的恢复方式。

以裁决为组织单位，不套用需求实现的多阶段模板。无文本冲突仍需报告检查过的语义范围；没有发现问题时明确范围和剩余不确定性，不虚构冲突或修改动作。
正文保留审批需要的接口变化、舍弃行为和兼容风险；详细 SHA、stage blob、命令和编辑位置放执行区。允许交叉引用，避免重复结论。复杂裁决可展开说明，不限定一行或固定句数。

## 完成标准与边界

- 每个裁决都说明双方意图、基线证据、推荐结果及对应验证；语义融合覆盖相关单侧与组合行为。
- 只允许写指定分析报告；未指定时使用默认位置。不编辑被分析文件，不暂存、提交、切换分支、启动/继续/终止 Git 操作。
- 用户要求只在对话输出或禁止写文件时，直接在对话给出报告。
- 文件动作清单是后续解决范围；额外冲突、来源变化、范围外修改或需要新决策时停止。
- 禁止建议 `git add .`，后续暂存应指定已审核文件。继续操作、提交、推送和恢复必须符合用户授权，不能将方案批准等同于全部授权。
- 恢复方式仅适用于已确认的操作状态，说明对已有修改的影响；不提供宽泛覆盖命令。
- 初始状态只标一次 `WAITING_FOR_APPROVAL`。计划执行的检查不能声称已经通过。
- 输出前检查正文能否支持裁决、执行清单能否落实裁决，以及是否遗漏自动合并产生的组合影响。

## 输出

默认路径：`.code/merge-review/合并分析-YYYYMMDD-HHMMSS.md`，重名时追加序号，不覆盖旧报告。
对话给出合并判断、文本冲突与语义问题数量、最高风险、未决问题和报告链接。
可选编码工具见 [scripts/README.md](scripts/README.md)；编码检查不能证明冲突解决正确。
