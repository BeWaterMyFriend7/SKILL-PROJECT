# Skill 文档结构优化建议

## 当前问题

两个 skill 的 SKILL.md 都过于冗长：
- `code-change-plan`: 282 行
- `code-merge-helper`: 135 行

大量细节规则混在核心流程中，导致：
1. AI 助手难以快速理解核心流程
2. 维护困难，规则分散
3. 用户难以快速上手

## 优化原则

### SKILL.md 应该包含什么（< 100 行）

✅ **核心执行流程** - 5-10 步骤的清晰流程
✅ **关键约束** - 必须遵守的铁律（3-5 条）
✅ **输入输出** - 触发条件和产出物
✅ **引用导航** - 指向详细文档的链接

### 应该移到 references/ 的内容

❌ 详细的章节填写规范
❌ 具体的验证规则
❌ 编码处理细节
❌ Git 命令参考
❌ 错误处理流程
❌ 扩展的示例

## 推荐结构

```markdown
---
name: skill-name
description: 一句话说明 skill 的作用和触发条件
---

# Skill Name

简要介绍（1-2 段）

## 核心流程

1. 步骤 1
2. 步骤 2
3. ...
4. 输出并停止

## 关键约束

- 约束 1
- 约束 2
- 约束 3

## 输入输出

**触发条件：** ...
**输出：** ...
**输出位置：** ...

## 详细文档

- 流程细节：`references/workflow.md`
- 报告结构：`references/structure.md`
- 质量检查：`references/quality.md`
- 编码规则：`../shared/encoding_reference.md`

## 快速开始

调用示例...
```

## 实施计划

### 第一阶段：创建精简版（不破坏现有）

1. 创建 `SKILL.compact.md` 作为精简版参考
2. 将详细规则整理到对应的 references 文档
3. 保留原 SKILL.md 不变

### 第二阶段：验证和切换（可选）

1. 在实际项目中测试精简版
2. 收集反馈
3. 如果效果好，用精简版替换 SKILL.md

### 第三阶段：文档重组

1. 清理 references 中的冗余内容
2. 建立清晰的文档导航
3. 添加快速参考卡片
