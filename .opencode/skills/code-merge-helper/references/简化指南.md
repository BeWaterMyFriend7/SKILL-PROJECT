# code-merge-helper 简化指南

## 简化版报告结构（5 章）

简化版报告从原来的 14 章精简为 5 章，更易读、更实用。

### 报告结构对比

| 简化版 | 原版（已弃用） | 说明 |
|--------|---------------|------|
| 1️⃣ 冲突概览 | 第 2-3 章 执行摘要与冲突清单 | 合并为一个概览表 |
| 2️⃣ 冲突分析 | 第 4 章 冲突详细分析 + 第 10 章 人工决策 | 保留核心分析，人工决策嵌入 |
| 3️⃣ 操作步骤 | 第 6-8 章 文件清单、执行顺序 | 简化为可执行的 bash 脚本 |
| 4️⃣ 验证清单 | 第 9 章 验证计划 | 简化为 Checkbox 列表 |
| 5️⃣ 风险与回滚 | 第 11-12 章 停止条件、残余风险 | 合并为风险评估和回滚命令 |
| - | 第 1 章 合并上下文 | 合并到标题区 |
| - | 第 5 章 行为保留矩阵 | ❌ 删除（过度设计） |
| - | 第 13 章 人工审批 | 简化为审批记录 |
| - | 第 14 章 执行指引 | ❌ 删除（用操作步骤代替） |
| - | 附录 A JSON 执行契约 | ❌ 删除（对人工审批无用） |

### 删除的内容

**过度设计的追踪系统：**
- ❌ C-01, D-01, B-01, A-01, V-01, HD-01, DP-01 等 7 种 ID 体系
- ❌ 行为保留矩阵（B-01）
- ❌ 逐文件实施清单（A-01）
- ❌ 影响范围评估矩阵

**复杂的执行规则：**
- ❌ 第 14 章详细的执行指引（7 个子章节）
- ❌ 执行前置校验（7 项检查）
- ❌ 范围守卫脚本
- ❌ 分层验证（6 层）
- ❌ 偏差处理流程

**冗余的数据格式：**
- ❌ 附录 A：JSON 执行契约
- ❌ JSON Schema 验证
- ❌ 复杂的验证脚本

### 保留的核心功能

**✅ 冲突识别**
- 冲突文件列表
- 冲突类型（逻辑、文本、依赖）
- 风险等级（🔴 高 / ⚠️ 中 / ✅ 低）

**✅ 三方对比**
- stage-2（当前分支）改了什么
- stage-3（合入分支）改了什么
- common-base（共同祖先）是什么状态

**✅ 推荐方案**
- 保留 stage-2 / stage-3
- 语义融合（保留两边）
- 需人工决策
- 包含具体的代码示例

**✅ 操作步骤**
- 可执行的 bash 命令
- 逐步的操作说明
- 验证命令

**✅ 风险与回滚**
- 风险评估
- 回滚命令（具体可执行）

## 使用建议

### 生成报告
```bash
# 先触发 Git 冲突
git merge feature-branch

# 调用 skill 分析
/code-merge-helper
```

### 审批报告
1. 阅读报告（5-8 分钟）
2. 确认推荐方案是否合理
3. 回答"待决策问题"
4. 修改状态为 `APPROVED`

### 执行合并
按照报告"第 3 章 操作步骤"执行：
```bash
# 1. 编辑冲突文件
# 2. 验证编译和测试
# 3. 完成合并
git add .
git commit
```

## 适用场景

**适合使用简化版：**
- ✅ 小团队（< 20 人）
- ✅ 快速迭代项目
- ✅ 冲突文件数 < 10
- ✅ 冲突点明确的合并

**可能需要完整版：**
- ⚠️ 大型团队（> 50 人）
- ⚠️ 严格审计要求
- ⚠️ 复杂的多模块冲突
- ⚠️ 需要 JSON 契约的自动化工具

目前只提供简化版，如需完整版可自行扩展模板。

## 关键差异

### ID 体系简化

**原版：**
```
C-01: 冲突
D-01: 决策
B-01: 行为保留
A-01: 允许修改
V-01: 验证项
HD-01: 人工决策
DP-01: 改动点
```

**简化版：**
- 只用文件名标识冲突
- 用风险等级标记（🔴 ⚠️ ✅）
- 直接描述，不使用 ID

### 人工决策方式

**原版：** 独立章节（第 10 章），包含数据流、改动点明细表、影响范围表

**简化版：** 嵌入到冲突分析中，用 ❓ 标记需要人工决策的问题

### 执行方式

**原版：** 
- 第 14 章提供详细的执行指引
- AI 按指引自动执行
- 需要验证脚本支持

**简化版：**
- 第 3 章提供操作步骤（bash 脚本）
- 人工按步骤执行（更安全）
- 不依赖复杂的验证脚本
