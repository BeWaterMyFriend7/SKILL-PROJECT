# Draw.io 质量规则

## 结构

- 使用 UTF-8 无 BOM、未压缩 XML；设置 `mxGraphModel grid="0"`。
- `mxGeometry` 必须包含 `as="geometry"`；可见节点使用 `width/height` 且尺寸为正数。
- 保证 ID 唯一、父子关系无循环、边的 source/target 引用存在。
- 将父子相对坐标换算为绝对坐标后再检查重叠、越界和包含关系。

## 颜色与字体

- 主题和派生令牌以 `theme-tokens.md`、`scripts/palette.py` 为准。
- 先应用主题视觉配方，再选择结构角色；普通卡片、浅容器、实色骨架和焦点必须形成至少三级明度层次。
- Tech Blue 的数据青可以承担主要容器或轴向结构，但必须按整层、整组或整轴使用；Vibrant 的状态色只表达真实状态。
- 正文对比度至少 `4.5:1`，大号或粗体至少 `3:1`。
- 使用 `Inter, Noto Sans SC, Microsoft YaHei, sans-serif`；页面标题通常 32～48，区域标题 18～24，分组标题 15～18，卡片标题 13～16，正文 12～14，辅助文字不小于 11。
- 浅色允许一个统一的轻微阴影预设；深色默认不用阴影。禁止纯黑背景、网格、强渐变、霓虹描边和重阴影。
- 新版模板和示例声明 `visualContract="enterprise-v2"`；主要节点声明 `colorRole`，并包含一个明确视觉焦点。
- `domain-app/domain-control/domain-network/domain-data` 只表达受控功能域；`status-success/status-warning/status-error` 只表达真实状态。

## 布局

- 页面边距通常 40px，硬下限 30px；同级元素等宽、等高、等距。
- 内容少时整体居中，内容多时增加行列、扩展画布或拆图，不缩小到字号下限以下。
- 内容利用率目标 55%～80%；低于 45% 检查空白，高于 85% 检查拥挤。
- 子元素完整位于父容器内；标题、正文、图例和连线不得越界或重叠。
- 架构图使用 `vertical-stack`，一级标题、一级容器、二级分组标题和三级标签使用独立元素。
- 架构层间距 28～40px；二级卡片间距 24～28px；标签间距 8～12px。
- 附加模块按 DSL 使用，不得替代主骨架。
- 页面必须有主标题、区域层和内容层的清楚差异；禁止所有节点使用同一种小矩形样式。

## 连线

- 只有包含、邻近和对齐无法表达的信息才使用连线。
- 优先短直线和正交线；不使用无必要斜线、曲线、蛇形回路或穿越节点的路径。
- 主流程使用主色实线，返回使用中性虚线，异步使用异步色虚线，错误使用错误色实线。
- 多线汇聚时使用汇聚节点、总线或拆图；架构图默认少箭头。

## 类型规则

- 数据架构至少保留 3 个有效主层，层级按需求增减；治理、安全和运维使用独立保障域。
- 流程图包含唯一主方向、起点、终点和完整判断出口。
- 状态图包含初始、终止和带标签的转换。
- 时序图包含参与者、完整生命线、起止语义、请求和返回；消息按时间向下。
- ER 图实体均匀排列，字段对齐，基数靠近端点；关系线不穿过实体。
- 时间线和路线图节点等距；总结图优先网格或分组。

## 图标与渲染

- 图标按 `icon-policy.md` 执行，Draw.io 中必须离线可见。
- 渲染后检查颜色、层级、文字、重叠、连线、空白和缩小可读性。
- 浅色与深色必须保持相同内容和几何结构。
- XML 合法不代表视觉合格；未完成真实渲染时明确标注。
