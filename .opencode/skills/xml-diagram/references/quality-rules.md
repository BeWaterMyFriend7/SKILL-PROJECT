# 质量与视觉规则

## 质量闭环

颜色、布局、重叠、字体、连线和空白必须在 DSL、XML、渲染三个阶段检查。XML 合法不代表视觉合格；无法渲染时必须明确标记未完成视觉验收。

## Draw.io XML

- UTF-8 无 BOM，XML 可解析。
- `mxGraphModel grid="0"`，最终图无网格、点阵或纹理。
- `mxGeometry` 必须包含 `as="geometry"`。
- 可见节点必须使用 `width/height`，禁止 `w/h`。
- 可见节点宽高必须为正数；不得静默跳过无尺寸节点。
- ID 唯一，边的 source/target 引用存在节点。
- 父子相对坐标必须换算为绝对坐标后再检查。
- 背景不参与边距、重叠和内容利用率计算。

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| canvas | `#F6F8FB` | `#0F172A` |
| surface | `#FFFFFF` | `#172033` |
| surface-muted | `#EEF3F8` | `#1E293B` |
| border | `#D8E1EA` | `#334155` |
| text-strong | `#172033` | `#F8FAFC` |
| text | `#475569` | `#CBD5E1` |
| text-muted | `#64748B` | `#94A3B8` |
| primary | `#2563EB` | `#60A5FA` |
| success | `#16A34A` | `#4ADE80` |
| warning | `#D97706` | `#FBBF24` |
| error | `#DC2626` | `#F87171` |
| async | `#7C3AED` | `#A78BFA` |
| storage | `#0891B2` | `#22D3EE` |

- 一张图使用一个主色，最多增加 1～2 个必要语义色。
- 正文对比度至少 4.5:1，大号或粗体至少 3:1。
- 禁止高饱和大色块、装饰渐变、重阴影和纯黑背景。
- 深色禁止阴影；浅色只允许克制的轻微阴影。
- 浅色和深色使用相同坐标、尺寸、圆角、间距、连线和图例位置。

## 布局与空白

- 页面推荐边距 40px，硬下限 30px；页面标题允许 20px。
- 普通图一级区域间距 32～36px；架构图一级层间距 28～40px；二级卡片间距 24～28px，标签间距 8～12px。
- 普通容器标题安全区高度 32～40px，内容必须从安全区下方开始。
- 架构图一级标题位于容器外部上方，与容器间距 8～12px；标题左侧与容器内容区左侧对齐。
- 架构图二级标题使用独立居中标题条，与首行内容间距 12～16px，并与卡片共用中心轴。
- 架构图容器高度由实际内容行数决定；最后一行不足时作为整体居中，不在左侧堆放。
- 同级元素默认等宽或遵循明确尺寸规律，间距差异不超过 4px。
- 内容较少时整体居中，禁止从左侧连续堆放。
- 左右留白差异建议不超过 16px；超过 120px 必须复核。
- 子元素必须完整位于父容器内部。
- 内容利用率目标 55%～80%；低于 45% 或高于 85% 必须复核。
- 不用放大空卡片填充画布，不用缩小字体容纳内容。

## 字体与组件

字体：`Inter, Noto Sans SC, Microsoft YaHei, sans-serif`。

| 层级 | 字号 | 字重 |
| --- | ---: | ---: |
| 页面标题 | 24～26 | 700 |
| 一级区域标题 | 18 | 700 |
| 二级卡片标题 | 15 | 600 |
| 正文 | 12 | 400 |
| 辅助文字 | 11 | 400 |

- 标题禁止下划线、装饰横线和按钮式背景。
- 架构一级容器、一级标题、二级卡片和二级标题必须分别使用独立 `mxCell`；一级标题不得成为一级容器的子元素。
- 内容标签可以把矩形与内部文字保留为一个元素。
- 文本过长时依次精简、换行、扩大节点、扩大画布或拆图。

## 通用连线

- 每条线必须表达无法由包含、分组、对齐或邻近表达的信息。
- 默认使用正交线或短直线，禁止长斜线和随意曲线。
- 连线不得穿过无关节点、标题区、正文或图例。
- 普通关系使用中性实线，主流程使用蓝色实线，错误使用红色实线，异步使用紫色虚线，返回使用灰色虚线。
- 多条线汇聚同一目标时优先分组、汇聚节点或总线。
- 架构图默认不画箭头；只保留关键数据流、跨区依赖、输入输出、错误或异步关系。

## 流程图

- 每张图只有一个主方向：左到右或上到下。
- 禁止第一行向右、第二行折返向左的蛇形流程。
- 节点超过 6～7 个或分支较多时优先改为上到下。
- 异常分支统一位于主轴一侧，不穿过主流程。
- 判断节点每个出口必须有标签，节点与结果至少间隔 32px。
- 必须包含 `flow-start` 和 `flow-end`。

## 状态图与生命周期

- 主状态链只使用一个方向。
- 每条状态转换必须有触发条件或动作标签。
- 双向转换使用分离路径，自循环贴近节点，回退线走主链外侧。
- 异常线不得穿过主状态链。

## 时序图

- 必须包含 `sequence-start`、`sequence-end`。
- 参与者使用 `participant-*`，生命线使用 `lifeline-*`。
- 每个参与者都有从参与者底部延伸到交互末端的完整竖向生命线。
- 消息使用 `message-*`，返回使用 `return-*`，消息必须水平。
- 时间严格从上到下，每条消息建议间隔 36～44px。
- 自调用位于生命线右侧，不能贴近或越过画布边缘。
- 默认参与者不超过 6 个，主要消息不超过 12 条；超过时拆图。

## 关系图

- 使用分层、中心辐射、分组或网格，禁止随机散点。
- ER 实体按领域分组，主外键和关系基数明确。
- 依赖关系保持统一方向，循环依赖单独警示。
- 知识关系限制跨主题连线，不把每个概念都连接到中心。
- 自动路由不能保证清晰时必须设置路径点，避免穿过实体。

## 渲染检查

- 核心结论能否在数秒内理解。
- 颜色是否协调、对比是否清晰。
- 区域、卡片和标签层级是否明确。
- 文字是否清晰、完整、无异常纵排或换行。
- 元素、文字、线条标签和图例是否重叠。
- 箭头是否必要，连线是否交叉、穿越或绕行。
- 是否存在大面积无意义空白或局部过度拥挤。
- 浅色和深色是否保持统一组件和布局体系。
