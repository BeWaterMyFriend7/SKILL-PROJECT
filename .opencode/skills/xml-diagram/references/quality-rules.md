## 质量闭环

同一问题在三个阶段检查：

| 维度 | DSL | XML | 渲染 |
| --- | --- | --- | --- |
| 颜色 | 语义与数量 | 色值与对比度 | 实际观感 |
| 布局 | 阅读方向与分组 | 坐标、间距、越界 | 平衡和易读性 |
| 重叠 | 密度风险 | 几何相交 | 文字、箭头和图例遮挡 |
| 字体 | 层级 | 字号和容纳空间 | 清晰、换行和裁切 |
| 连线 | 必要性和语义 | 引用、线型和路径 | 交叉、穿越和绕行 |
| 空白 | 分区和密度 | 内容包围盒 | 是否有设计意义 |

## 视觉系统

基础颜色：

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| canvas | `#F6F8FB` | `#0F172A` |
| surface | `#FFFFFF` | `#172033` |
| surface-muted | `#EEF3F8` | `#1E293B` |
| border | `#D8E1EA` | `#334155` |
| text-strong | `#172033` | `#F8FAFC` |
| text | `#475569` | `#CBD5E1` |
| text-muted | `#64748B` | `#94A3B8` |
| primary | `#2563EB` | `#60A5FA` |
| success | `#16A34A` | `#4ADE80` |
| warning | `#D97706` | `#FBBF24` |
| error | `#DC2626` | `#F87171` |
| async | `#7C3AED` | `#A78BFA` |
| storage | `#0891B2` | `#22D3EE` |

规则：

- 一张图使用一个主色，通常最多增加 1 至 2 个必要语义色；
- 颜色必须表达稳定语义，不为普通模块随机着色；
- 正文对比度至少 4.5:1，大号或粗体文字至少 3:1；
- 禁止高饱和大色块、装饰渐变、重阴影和纯黑背景；
- 深色禁止阴影；浅色只允许克制的轻微阴影；
- 浅色和深色使用相同坐标、尺寸、圆角、间距、连线和图例位置；
- `mxGraphModel` 必须显式设置 `grid="0"`，最终图不得出现网格、点阵或纹理。

## 布局与空白

- 页面安全边距 40，硬下限 30；
- 一级区域间距 36；二级卡片间距 28；三级标签间距 8；
- 同级节点沿网格对齐，尺寸一致或具有明确规律；
- 重要内容靠近主要阅读路径和视觉中心；
- 内容包围盒应在画布中视觉居中；
- 内容利用率目标 55% 至 80%，低于 45% 或高于 85% 必须复核；
- 检查左右、上下留白是否失衡，不能只看总体比例；
- 空白用于分组、聚焦和阅读时可以保留；无意义大面积空白必须通过重排或缩画布消除；
- 不用放大卡片填充画布，不用缩小字体容纳内容。

## 字体和组件

字体：`Inter, Noto Sans SC, Microsoft YaHei, sans-serif`。

| 层级 | 字号 | 字重 |
| --- | ---: | ---: |
| 页面标题 | 26 | 700 |
| 一级区域标题 | 18 | 700 |
| 二级卡片标题 | 15 | 600 |
| 正文 | 12 | 400 |
| 辅助文字 | 11 | 400 |

圆角：一级区域 14，二级卡片 10，三级标签 6。

- 一级内容必须有完整圆角容器、可见边界、标题安全区和内部留白；
- 区域标题、卡片标题和正文不得进入彼此安全区；
- 架构图分组卡片的容器不得承载标题文字；容器和标题必须是两个独立 `mxCell`，标题使用无填充、无边框的纯文字元素；
- 分组卡片标题区建议高度 32 至 40，内容标签必须从标题区下方开始；内容标签可将矩形与内部文字保留为一个元素；
- 标题禁止下划线、装饰横线和按钮式背景；
- 文本过长时依次精简、换行、扩大节点、扩大画布或拆图；
- 所有三级标签保持独立可编辑，不写成卡片内的项目符号文本；
- 渲染后检查字体清晰度、截断、异常换行和低对比。

## 通用连线

- 每条线必须表达无法由包含、分组、对齐或邻近表达的信息；
- 默认使用正交线或短直线，禁止随意曲线和长斜线；
- 连线不得穿过无关节点、标题区、文字和图例；
- 标签使用简短动词短语，放在路径清晰处；
- 普通关系使用中性实线，主流程使用蓝色实线，错误使用红色实线，异步使用紫色虚线，返回使用灰色虚线；
- 多条线汇聚同一目标时优先分组、汇聚节点或总线；
- 连线混乱时按顺序处理：删除非必要关系、调整节点、改变分组、统一阅读方向、增加汇聚节点、拆图，最后才调整折点。

## 架构图

表达优先级：空间位置 > 区域包含 > 层级分组 > 对齐和邻近 > 少量关键箭头。

- 业务架构图默认不使用箭头；
- 业务架构使用场景、能力、对象或资源分层；
- 应用架构突出入口、核心应用、数据和外部依赖；
- 技术架构按技术层次排列，治理、安全和观测作为跨切能力；
- 部署架构使用区域、网络、集群、节点和实例的嵌套边界；
- 只有关键价值链、跨区依赖、输入输出、核心数据流、错误或异步关系才画箭头；
- 禁止卡片之间形成网状箭头。

## 状态图

- 主状态链从左到右或从上到下，一张图只有一个主要方向；
- 主状态沿统一轴排列，失败、取消和回退状态放在轴线侧边；
- 每条转换必须有触发条件或动作标签；
- 双向转换使用分离路径，不得完全重叠；
- 自循环贴近节点，回退线走主流程外侧；
- 异常线不得穿过主状态链；
- 普通转换使用中性实线，主转换使用蓝色实线，异常使用红色实线，可选或异步转换使用紫色虚线。

## 时序图

- 必须具有明确的起点和终点表示；起点连接首个参与者，最终消息连接终点；
- 参与者横向排列并顶部对齐；
- 每个参与者都具有一条从中心竖向向下、从参与者底部延伸至交互末端的完整生命线；禁止只为发生首条消息的参与者绘制生命线；
- 时间严格从上到下推进；
- 消息箭头横向连接参与者，尽量保持水平；
- 同步请求使用实线箭头，异步消息使用紫色虚线或开放箭头，返回使用灰色虚线，错误返回使用红色虚线；
- 主要处理者使用与生命线对齐的窄激活条；
- 消息标签放在线上方，不遮挡生命线或激活条；
- 默认参与者不超过 6 个，主要消息不超过 12 条；超过时按阶段或场景拆图；
- 模板至少包含一次覆盖全部参与者的下游调用和完整返回链，避免生成图漏掉末端参与者的竖线或横向消息；
- 禁止流程图式菱形、步骤卡片和复杂折线。

## 关系图

- 优先使用分层、中心辐射、分组或网格，不使用随机散点；
- 高关联节点位于视觉中心，相关节点靠近所属分组；
- 默认不展示可推导的间接依赖；
- 双向关系优先使用单线双向箭头，不绘制两条重叠线；
- 多个节点连接同一目标时优先分组或汇聚；
- ER 实体按领域分组，字段左对齐，主外键和关系基数明确；
- 依赖图保持统一方向，循环依赖使用明确警示；
- 知识图限制跨主题关系，不把每个概念都连接到中心。

## 图例

只有存在无法自然理解的颜色、线型、状态、角色或边界语义时才生成图例。

- 优先底部紧凑横向图例，其次右侧紧凑纵向图例；
- 图例参与画布计算，不得覆盖或挤压主内容；
- 只有一个图例项时直接标注，不创建独立图例；
- 图例和主内容间距至少 24。

## 自动检查

- XML 可解析且为 UTF-8；
- `mxCell` ID 唯一，边引用存在；
- 每个 `mxGeometry` 包含 `as="geometry"`；
- `grid="0"`，无模板占位文字和标题下划线；
- 所有可见元素位于画布内且距边缘至少 30；
- 同级节点不重叠，文字字号不低于 11；
- 已知文字和背景颜色满足对比度；
- 内容利用率处于合理范围；
- 状态图、时序图和关系图没有明显过量或错误连线。

## 渲染检查

- 核心结论能否在数秒内理解；
- 颜色是否协调，是否存在多个视觉焦点；
- 区域、卡片和标签层级是否清楚；
- 文字是否清晰、完整且没有异常换行；
- 元素、连线标签和图例是否重叠；
- 箭头是否必要，是否交叉、穿越或绕行混乱；
- 是否存在大片无意义空白或局部拥挤；
- 浅色和深色是否保持统一风格。
