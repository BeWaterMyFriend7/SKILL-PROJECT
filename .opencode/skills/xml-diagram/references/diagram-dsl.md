# 图形 DSL

DSL 是生成 XML 前的内部蓝图，使用自然语言即可，不要求 JSON。目标是让 XML 阶段只做确定性排版，不再猜测内容或布局。

## 必填结构

```text
图形目标：向谁说明什么，核心结论是什么
图形类型：精确到模板名称
主题：light / dark
阅读方向：左到右 / 上到下 / 中心向外
画布策略：固定范围 / 根据节点数量扩展

叙事：
  - 起点或入口
  - 主阅读路径
  - 分支、异常或辅助关系
  - 终点或结论

区域：
  - 区域名称、层级和语义
  - 布局模式：distributed / grid / centered / stack / nested
  - 行列数量、等宽要求
  - 内边距、标题安全区和区域间距

节点：
  - ID、名称、类型、所属区域
  - 标题、正文或标签
  - 重要程度和颜色角色
  - 尺寸约束和换行预期

关系：
  - 起点、终点、方向和标签
  - 同步、异步、返回、异常或普通关系
  - 是否允许折线、汇聚或自调用

质量预期：
  - 不重叠、不越界、文字清晰
  - 同级均匀分布，内容整体居中
  - 连线不穿过无关节点或标题
  - 无无意义大面积空白或局部拥挤
  - 浅色和深色保持相同几何结构

假设：
  - 已确认事实
  - 合理推断
  - 需要用户确认的内容
```

## 布局模式

- `distributed`：同级元素等宽或按规律宽度，在容器内均匀分布。
- `grid`：按明确行列排布，同行同列对齐。
- `centered`：内容较少时作为整体居中，不从左侧堆放。
- `stack`：使用单一纵向或横向主轴分层。
- `nested`：用于部署边界、网络、集群和节点的嵌套包含。

DSL 必须明确使用哪一种模式，不使用“合理排列”“适当留白”等无法执行的描述。

## 图形类型补充字段

### 架构图

- 分层依据：场景、能力、应用、技术、区域或资源。
- 核心层和视觉中心。
- 哪些关系必须画箭头，其余通过包含、邻近和对齐表达。
- 分组卡片标题和内容标签分别列出。
- 每个一级标题的位置、宽度和与容器的间距；一级标题必须位于容器外部上方并左对齐。
- 每层的卡片列数、内容行数和等宽等距策略；最后一行不足时说明整体居中方式。
- 二级标题条必须独立且水平、垂直居中，并与内容标签共用中心轴。
- 二级标题到首行内容的精确间距，以及容器高度随内容行数收缩或扩展的策略。

### 数据架构图

- 先列出候选层及其处理决定：`保留 / 合并 / 删除 / 拆分 / 新增`，并说明与用户需求的对应理由；不得为了套模板保留空层。
- 候选层可从数据源、接入、传输缓冲、计算加工、存储模型、数据服务、数据应用开始分析，但名称、数量和边界必须按实际系统调整。
- 每个有效主层列出层名、职责、核心数据对象或组件，以及输入和输出；区分实时链路、离线链路和共享环节。
- 模型部分说明是否需要 ODS、DWD、DWS、ADS 或其他模型分层；没有数仓分层需求时不得强行套用。
- 每个数据层继续拆为二级分组卡片，并分别列出卡片标题和内容标签；禁止把层标题做成容器内部的大色块，也禁止把所有节点直接平铺。
- 数据治理、数据安全、平台运维等贯穿能力单独列为标准架构区域，内部继续使用同款二级分组卡片；不需要的能力可以删除。
- 主数据流明确起点、终点和自上而下的层间顺序；只列层间聚合关系和必要分支，表级或字段级血缘转为关系图。
- 明确主层顺序、二级卡片列数、卡片内标签行数、动态容器高度，以及浅色和深色共享的几何结构。

### 流程图

- 唯一主方向。
- 主流程节点顺序。
- 判断条件及每个出口标签。
- 异常分支位于主轴哪一侧。
- 节点过多时扩大画布还是改成纵向流程。

### 状态图与生命周期

- 初始、终止状态。
- 主状态链。
- 每条转换的触发条件或动作。
- 回退、取消和异常状态的位置。

### 时序图

- 参与者顺序。
- 每个参与者的完整生命线范围。
- 请求、返回、异步、异常消息及其纵向顺序。
- 激活条和自调用。
- 起点连接首个参与者，最终消息连接终点。

### 关系图

- 使用分层、网格、中心辐射还是分组。
- 主关系与可省略的间接关系。
- ER 图列出主外键和基数。
- 依赖图统一方向并标识循环依赖。
- 知识图限制跨组连接。

### 结构化内容

- 对比和矩阵明确行列含义。
- SWOT 固定四象限。
- 时间线明确时间轴、节点和卡片方向。
- 路线图明确阶段顺序、持续时间和上下交错规则。
- 总结图明确卡片网格和视觉重点。
