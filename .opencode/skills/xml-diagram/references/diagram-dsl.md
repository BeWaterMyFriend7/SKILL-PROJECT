# Draw.io 图形 DSL

在生成 XML 前，用自然语言写出以下蓝图。字段必须具体、可执行，不使用“合理排列”“适当留白”等模糊描述。

## 基础结构

```text
图形目标：受众、要说明的问题、核心结论
图形类型：精确到模板
视觉主题：Tech Blue｜科技蓝（默认）/ Vibrant ｜活力 / Mint green｜清爽绿 / Steady Red & Blue｜稳重红蓝
显示模式：light / dark
颜色覆盖：primary / secondary / tertiary / accent（可选，#RRGGBB）
阅读方向：左到右 / 上到下 / 中心向外
画布策略：固定尺寸 / 随内容扩展
主布局：架构图使用 vertical-stack；其他类型写明主轴
附加模块：无 / top-band / aux-column / callout / numbered-flow / focus-node / footer-band
图标策略：不用图标，或列出节点与图标的信息价值

区域：
- 名称、顺序、职责、布局模式、尺寸和内边距

节点：
- ID、名称、类型、所属区域、文字、颜色角色、尺寸和换行

关系：
- 起点、终点、方向、语义、线型、标签和路径通道

质量预期：
- 不重叠、不越界、文字清晰、同级均匀、连线不穿越、无无效空白

假设：
- 已确认事实、合理推断、待确认信息
```

## 布局模式

- `distributed`：同级元素按规律等宽、等距铺开。
- `grid`：按明确行列对齐。
- `centered`：少量内容整体居中。
- `stack`：使用单一横向或纵向主轴。
- `nested`：表达网络、地域、集群和部署边界。

架构图固定使用 `vertical-stack` 纵向分层，层内可横向排列。附加模块由内容决定，通常少量使用，但不设机械数量阈值；不得改变主层顺序或依靠扩大空画布容纳内容。

## 类型补充

### 架构图

- 写明分层依据、主层顺序、核心层和视觉中心。
- 写明每层分组数、卡片列数、末行居中方式和动态高度。
- 区分一级区域、二级分组标题和三级内容标签。
- 只保留关键调用、流量或数据流，其余关系用包含、邻近和对齐表达。

### 数据架构

- 对候选层逐项决定保留、合并、删除、拆分或新增，禁止空层。
- 写明实时、离线和共享链路；只有需要数仓分层时才使用 ODS/DWD/DWS/ADS。
- 将治理、安全、运维作为独立保障域；详细表级或字段级血缘另绘关系图。

### 流程、状态与生命周期

- 写明唯一主方向、起点、终点、步骤顺序和完整分支标签。
- 将异常或回退路径放在主轴一侧，不采用蛇形折返。
- 状态转换必须包含触发条件或动作。

### 时序图

- 写明参与者顺序、完整生命线、消息时间顺序、请求、返回、异步、异常和自调用。
- 消息保持水平或短距离正交，时间严格向下。

### 关系与结构化图

- ER 图列出实体、字段、主外键和基数；依赖图统一方向；知识图限制跨组连线。
- 对比和矩阵写明行列语义；SWOT 固定四象限。
- 时间线、路线图写明顺序、阶段和间距；总结图优先网格或分组。
