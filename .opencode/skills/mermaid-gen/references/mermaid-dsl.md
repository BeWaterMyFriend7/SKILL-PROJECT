# Mermaid 自然语言图形 DSL

先用自然语言规划图，再生成 Mermaid。DSL 不使用 JSON，不强制保存为文件；目标是选对图型、控制复杂度并减少自动布局中的线条混乱。

## 基础结构

```text
图形目的：
图形类型：
输出形式：Mermaid 代码块 / Markdown 文件
输出主题：light / dark
方向：TD / LR / RL / BT / 图型默认
核心结论：读者第一眼应看到什么

节点、参与者或实体：
- 名称、角色、顺序、所属分区

关系或消息：
- 起点、终点、含义、顺序、条件或基数

分区或阶段：
- 标题、顺序、包含内容、嵌套层级

复杂度：
- 节点数、关系数、分区数、是否需要拆图

检查要求：
- 围栏、语法、起止、分支、线条、标签和真实渲染
```

## Flowchart

- 定义开始、结束、步骤、判断、每个判断出口和汇聚点。
- 主流程保持单一方向，不蛇形折返。
- 判断出口标记“是/否”或明确业务条件。
- 架构类 flowchart 尽量少用箭头；关系复杂时改用 block 或 sequence。

## Sequence diagram

- 定义参与者横向顺序和消息时间顺序。
- 请求使用实线箭头，返回使用虚线箭头。
- 条件、可选和循环分别使用 `alt`、`opt`、`loop`。
- 参与者建议不超过 8 个，消息过多时拆分主流程和异常流程。

## Class diagram

- 定义类、核心属性或方法、继承、实现、聚合和组合关系。
- 只保留有助于理解设计的成员，不复制完整源码。

## ER diagram

- 定义实体、核心字段、PK、FK、关系和基数。
- 实体过多时按领域拆图，不使用 flowchart 方框模拟 ER。

## State diagram

- 定义 `[*]` 初始状态、终止状态、状态集合和触发条件。
- 避免同一状态间大量双向转换；异常路径单独组织。

## Block diagram

- 用于静态系统模块和分层架构，建议 2-4 列。
- 模块按层级或阅读顺序排列，默认减少箭头。
- 复杂调用链、网络拓扑和精确部署边界改用其他图型或工具。

## Gantt

- 定义标题、`dateFormat`、阶段、任务、状态、依赖和里程碑。
- 日期格式统一，避免把无依赖任务强行串联。

## 其他图型

- `gitGraph`：定义主干、分支、提交和合并顺序。
- `journey`：定义阶段、用户任务、满意度和参与角色。
- `pie`：类别不宜过多，数值必须能比较。
- `mindmap`：层级不超过 4 层，不添加连线语义。
- `timeline`：按时间顺序列出关键事件，说明保持简短。
- `quadrantChart`：定义两个轴含义、范围和候选项位置。
- `xychart-beta`：定义轴、单位和序列，数值数量保持一致。
- `sankey-beta`：定义来源、去向和非负流量，减少节点数量。

## 拆图条件

满足任一条件时优先拆图：节点超过 20、参与者超过 8、分区超过 8、嵌套超过 3 层、同一节点连接超过 6 条、出现多条跨区回线，或渲染后标签明显拥挤。
