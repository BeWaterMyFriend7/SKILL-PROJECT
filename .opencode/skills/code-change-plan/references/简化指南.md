# code-change-plan 简化指南

## 简化版报告结构（4 章）

简化版报告从原来的 7 章精简为 4 章，更易读、更实用。

### 报告结构对比

| 简化版 | 原版（已弃用） | 说明 |
|--------|---------------|------|
| 1️⃣ 要做什么 | 第 1 章 基本信息与需求分析 | 保留核心需求和验收标准 |
| 2️⃣ 怎么做 | 第 2-3 章 当前实现与目标方案 | 合并为技术方案和关键决策 |
| 3️⃣ 改哪些 | 第 4 章 影响范围与文件清单 | 保留文件清单（白名单） |
| 4️⃣ 如何验证 | 第 5-6 章 实施顺序与验证 | 简化为验证步骤和风险 |
| - | 第 7 章 执行契约与审批 | 简化为审批记录 |

### 删除的内容

**过度设计的追踪系统：**
- ❌ REQ-01, AC-01, CU-01, V-01 等 7 种 ID 体系
- ❌ 追踪矩阵（REQ → AC → CU → V）
- ❌ 旧逻辑退役矩阵（LR-01）
- ❌ 影响矩阵（IMP-01）

**复杂的执行规则：**
- ❌ 13 条执行规则
- ❌ 7 条停止条件
- ❌ 6 条禁止事项
- ❌ Windows 文件编辑指南

**冗余信息：**
- ❌ 修改单元（CU）详细描述
- ❌ 实施顺序表（由 AI 自行判断）
- ❌ 详细的完成条件定义

### 保留的核心功能

**✅ 需求分析**
- 需求列表（Checkbox 格式）
- 验收标准
- 待决策问题

**✅ 方案设计**
- 技术方案概述
- 关键决策及理由
- 流程对比（当前 vs 目标）

**✅ 文件清单（白名单）**
- 明确列出允许修改的文件
- 使用 ✏️ ➕ ❌ 标记操作类型
- 说明影响范围

**✅ 验证方案**
- 验证步骤（可执行命令）
- 验证清单（Checkbox）
- 风险评估和回滚方案

## 使用建议

### 生成方案
```bash
/code-change-plan

需求：<需求描述>
```

### 审批方案
1. 阅读方案（3-5 分钟）
2. 确认文件清单和验证步骤
3. 修改状态为 `APPROVED`

### 执行方案
```bash
读取并执行：.code/change-plans/<plan-id>.md
```

## 适用场景

**适合使用简化版：**
- ✅ 小团队（< 20 人）
- ✅ 快速迭代项目
- ✅ 改动文件数 < 20
- ✅ 需求明确的功能开发

**可能需要完整版：**
- ⚠️ 大型团队（> 50 人）
- ⚠️ 严格审计要求
- ⚠️ 复杂的多模块重构
- ⚠️ 需要详细的可追溯性

目前只提供简化版，如需完整版可自行扩展模板。
