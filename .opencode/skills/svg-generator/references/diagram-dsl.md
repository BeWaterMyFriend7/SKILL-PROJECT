# SVG 图形描述 DSL

先用自然语言完整描述图，再生成 SVG。DSL 不要求固定 JSON 格式，也不强制落盘；目标是消除布局、层级和连线歧义。

## 基础结构

```text
图形目的：
图形类型：
受众与场景：
输出主题：light / dark
质感等级：clean / polished / editorial
画布与方向：宽高、横向/纵向、阅读方向
核心结论：读者第一眼应看到什么

一级区域：
- 区域名称、顺序、职责、尺寸权重

二级分组：
- 所属区域、标题、内容项、排列方式

节点：
- 名称、类型、层级、重要度、状态或语义色

关系：
- 起点、终点、含义、方向、线型、标签、建议路径

视觉策略：
- 焦点、图标、阴影、渐变、强调色、图例

检查要求：
- 均匀、重叠、文字、连线、空白、对比度、缩小可读性
```

## 布局描述要求

- 明确每个一级区域是横排、竖排、嵌套还是侧栏。
- 明确同级元素的列数、等宽规则和间距。
- 明确标题位于容器外、标题栏内或卡片内部，不使用“适当排布”等模糊描述。
- 明确内容较多时是扩展画布、增加行数还是拆图。
- 明确图例位置；没有多重语义时不生成图例。

## 架构类

### 业务架构

优先描述业务场景、能力域、业务对象或资源层。能力域是视觉主体；一级标题位于区域容器上方，分组标题与内容标签分离。

### 应用架构

描述入口、核心应用、支撑应用、数据或外部依赖。静态归属主要依靠分区，只有关键调用或数据流使用箭头。

### 技术架构

描述技术层级、每层组件和安全、治理、可观测等横切能力。各层内容等距铺满可用宽度，不允许全部堆在左侧。

### 部署架构

描述地域、网络、子网、集群、节点和存储边界。先规划嵌套关系，再规划跨边界连线，避免节点与边界标题重叠。

### 数据架构

从用户目标推导实际层级，可从数据源、接入、传输缓冲、计算加工、存储模型、数据服务和数据应用中增减；禁止机械保留空层。数据治理、数据安全和平台运维可作为侧栏或底栏横切区域。主数据流使用少量聚合箭头，不把每个卡片逐一串联。

## 流程与行为类

### 线性流程

定义开始、按单一主轴排列的步骤、异常分支和结束。主轴不得蛇形折返。

### 分支流程

定义判断条件、每个出口标签、分支区域和汇聚点。分支在同一层展开，避免交叉回线。

### 生命周期

定义阶段顺序、每阶段目标、关键产物和阶段门。若阶段具有回环，使用外围通道。

### 状态图

定义初始状态、终止状态、状态集合以及每条转换的触发条件。转换标签靠近连线且不覆盖节点。

### 时序图

定义参与者横向顺序、每个参与者的完整生命线、消息自上而下顺序、请求/返回语义、激活区间、起点和终点。消息必须横向或短距离正交，不用斜线连接不同时间层。

## 关系类

### ER 图

定义实体、字段、PK/FK、关系和基数。实体字段按行对齐，关系线使用专用通道，不穿过实体。

### 依赖关系

定义依赖方向、层级和循环风险。优先分层布局，减少跨层长连线。

### 知识关系

定义中心主题、一级概念和二级关系。限制每个节点的连线数量，必要时拆分主题，禁止自由散点。

## 信息表达类

- 对比图：定义相同维度和左右或多列对齐方式。
- 决策矩阵：定义候选项、评价维度、权重、得分和推荐结论。
- SWOT：定义四象限及每象限条目，四区尺寸一致。
- 时间线：定义时间顺序、节点间距、事件位置和里程碑等级。
- 路线图：定义阶段、时间范围、工作流泳道和关键节点。
- 总结图：定义中心结论、主题分组和每组要点，避免纯文字堆叠。

## SVG 专属字段

- 图标策略：默认无图标；使用时只能选择一种线性或填充风格。
- 阴影策略：浅色最多一个全局轻阴影；深色不使用明显阴影。
- 渐变策略：`clean` 禁止；`polished` 通常禁止；`editorial` 最多一种克制渐变。
- 焦点区域：最多一个主要焦点，依靠尺寸、边框或小面积强调色突出。
- 图层顺序：背景、装饰、区域、连线、节点、文字、图例。
- 可访问性：给出适合 `<title>` 和 `<desc>` 的简短自然语言。
