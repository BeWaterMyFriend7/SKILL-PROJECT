# SVG 自然语言图形 DSL

先用自然语言完整描述图，再生成 SVG。DSL 不使用 JSON，不强制保存为文件；目标是消除层级、尺寸、布局和连线歧义。

## 基础结构

```text
图形目的：
图形类型：
受众与场景：
输出主题：light / dark
画布与方向：横向或纵向、阅读方向、预估宽高
核心结论：读者第一眼应看到什么

一级区域：
- 名称、顺序、职责、布局方向、尺寸权重

二级分组：
- 所属一级区域、标题、列数、宽高和间距

三级内容：
- 所属二级分组、名称、卡片宽高、每行数量和换行方式

关系：
- 是否必须连线；起点、终点、含义、线型、标签和建议通道

视觉策略：
- 浅色或深色、主色、语义色、是否需要图例

检查要求：
- 均匀、重叠、文字、连线、空白、对比度、缩小可读性
```

## 布局描述要求

- 明确每个一级区域是横排、竖排、嵌套还是侧栏。
- 明确同级元素的列数、宽高、间距、容器内边距和换行方式。
- 明确一级标题、二级标题和三级内容的位置，不使用“适当排布”等模糊描述。
- 明确内容较多时扩展画布、增加行数还是拆图。
- 没有多重线型或颜色语义时不生成图例。

## 架构类

架构图默认整体纵向分层、层内横向排列。一级标题可在容器顶部居中；二级标题独立居中；三级内容使用 `28-34px` 高的紧凑卡片。默认无箭头，只有不可缺少的调用、流量或主数据流使用少量正交线。

### 业务架构

描述业务场景、业务能力、业务服务、业务对象或资源层。能力层是视觉主体，同层卡片均匀铺满，不画角色到每个能力的长箭头。

### 应用或系统架构

描述入口、应用层、核心系统、支撑系统、数据资源和外部依赖。静态归属依靠分层和容器表达。

### 技术架构

描述终端、接入、网关、服务、数据、基础设施及横切技术能力。同层技术组件等宽、等距，不集中在左侧。

### 部署架构

描述访问入口、流量接入、地域、网络、集群、节点、存储和运维边界。部署边界与运维保障分开；只有关键访问路径使用连线。

### 数据架构

从需求推导数据源、接入、传输缓冲、计算加工、存储模型、数据服务和数据应用等层，可增减但不得机械保留空层。数据治理、数据安全和平台运维作为侧栏或底栏保障域。主数据流使用聚合箭头，不逐卡片串联。

## 流程与行为类

- 线性流程：定义起点、单一主轴步骤、必要异常分支和终点，禁止蛇形折返。
- 分支流程：定义判断条件、所有出口标签、独立分支通道和汇聚点，避免交叉回线。
- 生命周期：定义阶段、目标、产物和阶段门，回环使用外围通道。
- 状态图：定义初始、终止状态及触发条件，转换标签不得覆盖节点。
- 时序图：定义参与者顺序、完整生命线、消息时间顺序、请求、返回、激活区间、起点和终点；消息横向或短距离正交，不使用斜线表达时间。

## 关系类

- ER 图：定义实体、字段、PK/FK、关系和基数；实体采用均匀网格，关系使用专用正交通道。
- 依赖关系：定义依赖方向和层级，聚合公共依赖，减少跨层长线。
- 知识关系：定义中心主题和分组概念，限制单节点发散数量，禁止自由散点。

## 信息表达类

- 对比图：定义统一维度和列对齐方式。
- 决策矩阵：定义候选项、维度、权重、得分和结论。
- SWOT：四象限等宽等高。
- 时间线：定义时间顺序、等距节点和里程碑等级。
- 路线图：定义阶段、时间范围、泳道和关键节点。
- 总结图：定义中心结论、主题分组和每组要点，优先网格而非发散箭头。

## SVG 专属要求

- 默认无图标；使用时只采用一种风格。
- 浅色最多使用一个极轻全局阴影；深色不使用明显阴影。
- 默认不使用渐变；不得用效果掩盖层级和布局问题。
- 最多一个主要焦点，依靠尺寸、边框或小面积主色突出。
- 图层顺序为背景、区域、连线、节点、文字、图例。
- 为 `<title>` 和 `<desc>` 准备简短自然语言。
