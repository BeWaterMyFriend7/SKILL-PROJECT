# SVG 图形 DSL

生成 SVG 前先写自然语言蓝图。字段必须具体、可执行，不使用 JSON，也不使用“适当排布”等模糊描述。

## 基础结构

```text
图形目标：受众、要说明的问题、核心结论
图形类型：精确到模板
视觉主题：tech-blue（默认）/ vibrant / focused
显示模式：light / dark
颜色覆盖：primary / secondary / tertiary / accent（可选，#RRGGBB）
画布：阅读方向、预估宽高、扩展策略
主布局：架构图使用 vertical-stack；其他类型写明主轴
附加模块：无 / top-band / aux-column / callout / numbered-flow / focus-node / footer-band
图标策略：不用图标，或列出节点与图标的信息价值

一级区域：
- 名称、顺序、职责、布局方向和尺寸权重

二级分组：
- 所属区域、标题、列数、宽高、间距和内边距

三级内容：
- 所属分组、名称、卡片尺寸、每行数量和换行

关系：
- 起点、终点、语义、线型、标签和路径通道

检查：
- 均匀、重叠、越界、文字、连线、空白、对比度和缩小可读性
```

## 架构图

- 固定使用 `vertical-stack` 纵向分层，层内可横向排列。
- 写明主层顺序、分组数量、卡片列数、末行居中方式和动态高度。
- 静态归属用容器和位置表达；只为关键调用、流量和主数据流使用少量正交线。
- 附加模块由内容决定，通常少量使用但不设机械数量阈值；不得改变主层顺序。
- 业务架构写明场景、能力、服务和对象；应用架构写明入口、核心系统、支撑系统、数据和外部依赖。
- 技术架构写明终端、接入、服务、数据和基础设施；部署架构写明地域、网络、集群、节点和运维边界。
- 数据架构按需求增减数据源、接入、传输、计算、存储、服务和应用层；治理、安全、运维使用独立保障域。

## 流程与行为

- 线性流程：唯一主轴、起点、步骤、终点，不蛇形折返。
- 分支流程：写明判断出口、独立通道、异常分支和汇聚点。
- 生命周期与状态：写明阶段或状态、触发条件、回退、异常和终止。
- 时序图：写明参与者顺序、完整生命线、消息时间顺序、请求、返回、异步、异常和自调用。

## 关系与结构化图

- ER 图写明实体、字段、主外键和基数；实体使用均匀网格。
- 依赖图统一方向并聚合公共依赖；知识图限制单节点发散和跨组连线。
- 对比和矩阵写明行列语义；SWOT 固定四象限。
- 时间线和路线图写明顺序、阶段、时间范围和间距。
- 总结图优先使用网格或分组，不用多条中心发散箭头表达包含。

## SVG 专属

- 使用 `<tspan>` 处理多行文字，提供简洁 `<title>` 和 `<desc>`。
- 最多一个主要焦点，使用尺寸、边框或小面积 accent 强调。
- 图层顺序为背景、区域、连线、节点、文字、图例。
- 图标按 `icon-policy.md` 执行；效果不得掩盖层级或布局问题。
