# 图形目录与视觉骨架

模板和示例统一使用 `enterprise-v2` 视觉合同与 `fresh-catalog-v1` 生成标记。模板只提供结构起点；每次生成都必须根据自然语言内容重新计算节点、尺寸、间距、连线和结构颜色角色。

| 视觉骨架 | 图形类型 | 布局重点 |
| --- | --- | --- |
| 分层 | 业务、应用、技术、部署、数据架构 | 保持纵向分层；横向能力、侧栏与焦点按内容少量加入 |
| 流程 | 线性流程、分支流程、状态、生命周期 | 主链清楚；分支、补偿、反馈只在语义需要时出现 |
| 关系 | ER、依赖、知识关系、总结 | 中心或主实体突出；关系线不穿节点；标签贴近关系 |
| 矩阵 | 对比、决策矩阵、SWOT | 同维度对齐；色彩表达语义差异，不随机轮换 |
| 时间/交互 | 时间线、路线图、时序 | 时间或消息顺序不可歧义；返回、里程碑和阶段有明确层次 |

共 19 种类型，每种类型在 `templates/` 与 `examples/` 中恰好各一份。普通图标通常使用 0～4 个；不设硬上限，但只在识别、导航或语义确有帮助时增加。

全目录回归以 `test-outputs/diagram-types/catalog/requests.json` 的 19 条自然语言需求为输入，同一场景同时生成 SVG 与 Draw.io，并以真实渲染图验收。禁止把旧模板或旧示例作为批量换色输入。
