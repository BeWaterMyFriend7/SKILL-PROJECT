# code-change-plan 使用说明

## 适用场景

- 新增功能、修改行为、修复缺陷或重构前分析方案。
- 还原当前实现，分析目标变化及其上下游影响。
- 生成人可审批、AI 可精确执行的变更计划。
- 只负责规划，不修改业务代码。

## 快速使用

~~~text
请使用 code-change-plan 分析新增用户登录功能，先生成方案，不修改代码。
~~~

- 完整输出示例：[examples.md](examples.md)
- 执行规则：[SKILL.md](../../.opencode/skills/code-change-plan/SKILL.md)
- 报告模板：[change-plan-template.md](../../.opencode/skills/code-change-plan/assets/change-plan-template.md)

## 它如何工作

Skill 会先在内部完整分析：

1. 需求、验收、已确认决策和禁止范围。
2. 当前入口、调用链、数据或状态、配置、错误和测试。
3. 每个功能点从当前到目标如何变化。
4. 变化对调用方、消费者、兼容性、安全、运维、测试和文档的影响。
5. 必须保持的行为、文件落点、验证和停止条件。

内部分析不原样倾倒到报告。报告先给人两部分：

- **方案结论：** 最终结果、核心做法、主要影响、风险和待决策事项。
- **关键变化：** 当前情况、修改后行为及主要影响。

精确文件、符号、保护项、验证和停止条件放在后面的 **AI 执行清单**。

## 核心规则

- 分析深度不受报告篇幅限制；精简只删除重复和无决策价值的内容。
- 文件白名单必须从功能变化和影响分析推导。
- 涉及调用链、状态流或顺序时，就地说明流程变化；其他功能不生成空流程栏目。
- 一项事实只出现一次，没有内容的可选区块直接省略。
- 新行为、重要保持项和兼容性都必须有可判断的验证。
- 出现白名单外修改、关键假设失效或关键验证失败时停止并重新审批。
- 计划初始状态为 `WAITING_FOR_APPROVAL`，状态只出现一次。

需要处理 Windows UTF-8 编码时，可使用 Skill 内的 `scripts/write_utf8.py`。
