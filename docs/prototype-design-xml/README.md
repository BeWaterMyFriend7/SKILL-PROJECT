# prototype-design-xml 使用说明

`prototype-design-xml` 根据自然语言需求或需求文档生成简约、可在 Draw.io/diagrams.net 中继续编辑的 `.drawio` XML 页面原型，适合需求评审、页面结构讨论和快速调整。

## 输入与输出

- 输入：原型目的、用户角色、页面范围、核心任务、设备类型和可选主题。
- 输出：未压缩、UTF-8、可编辑的 `.drawio` 文件。
- 用户未指定目录时输出到项目根目录 `output/prototype/drawio`。
- DSL 只在生成过程中作为内部分析依据，默认不创建或输出 DSL 文件。
- 默认不生成 README、Markdown、JSON 或图片资源等中间产物。

## 主要流程

1. 分析用户、页面范围和核心任务。
2. 规划页面清单、导航和页面关系。
3. 在内部形成自然语言原型 DSL，明确画框、区域、组件、状态和布局，不落盘为 DSL 文件。
4. 参考基础模板生成 Draw.io XML。
5. 检查 XML、ID、页面、父级、尺寸和可编辑性。
6. 在 Draw.io 中打开或导出图片，检查重叠、字体、对齐、空白和连线。
7. 修正问题后只交付最终 `.drawio`。

## 简约设计原则

- 默认 `grid=0`、`shadow=0`，不使用渐变、纹理和背景网格。
- 页面标题和区域标题使用独立文字元素。
- 使用普通矩形、文字、分割线、1px 边框和轻微圆角。
- 普通页面不画跳转箭头，使用页面编号和文字注释表达关系。
- 不把页面导出为整页位图嵌入，保留组件可编辑性。

## 与 HTML 原型的区别

- XML 原型适合在 Draw.io 中评审、移动和修改组件。
- 需要真实按钮、表单和弹窗交互时使用 `prototype-design-html`。
- 两种原型共享简约的页面层级、配色和组件尺寸，但输出和验证方式不同。

## 示例

- [红包运营后台原型](drawio/red-packet-prototype.drawio)：三个独立页面，覆盖概览、活动列表和创建表单。
- [消息聊天原型](drawio/chat-prototype.drawio)：单页移动端聊天界面，覆盖状态、消息气泡和输入区。
