# 图形 Skills 稳定性与视觉统一优化方案

**Plan ID:** `diagram-skills-quality-20260711-150509`
**创建时间:** 2026-07-11 15:05:09 +08:00
**审批状态:** APPROVED
**实施状态:** COMPLETED
**风险等级:** 中高
**审查范围:** `svg-generator`、`xml-diagram`、`mermaid-gen`
**执行约束:** 本方案仅用于审查和规划；审批前不得修改现有 skill、模板、示例或校验脚本。

## 1. 基本信息与需求分析

### 1.1 优化目标

- **REQ-01 出图稳定：** 建立统一的“意图识别 → 中间结构 → 模板选择 → 布局 → 样式 → 校验 → 渲染检查”流程，减少风格漂移、结构混乱和质量波动。
- **REQ-02 功能定位清晰：** 三个 skill 按输出媒介划定接口，避免都被“流程图、架构图、画图”等泛化关键词同时触发。
- **REQ-03 模块划分合理：** 每个 skill 都是一个完全自包含的深模块，在自己的目录内拥有意图分类、中间结构、视觉标记、质量契约、架构构图规则、模板、示例和校验实现；单独复制任一 skill 文件夹即可使用。
- **REQ-04 视觉风格统一：** 统一浅色/深色主题、色彩角色、文字层级、圆角、边框、间距、连线和图例语言。
- **REQ-05 提升架构图质感：** 为业务、应用、技术、部署、系统架构建立独立构图原型和高级感验收基线。
- **REQ-06 避免常见问题：** 自动或半自动发现布局不合理、留白异常、颜色混乱、文字过小、重叠遮挡、拥挤和越界。

### 1.2 推荐功能边界

| Skill | 推荐接口 | 核心优势 | 不应承担 |
| --- | --- | --- | --- |
| `svg-generator` | 用户明确要 SVG、浏览器可直接展示、静态高质量矢量图，或泛化“做一张高级架构图” | 精确视觉控制、适合展示和嵌入网页 | 不负责 Draw.io 可编辑性；不以 Mermaid 代码为交付物 |
| `xml-diagram` | 用户明确要 Draw.io、diagrams.net、XML、可编辑图形 | 可编辑、模板化、结构化布局、可做严格 XML 校验 | 不接管泛化“画图”触发；不输出 Mermaid/SVG |
| `mermaid-gen` | 用户明确要 Mermaid、Markdown 内嵌、文档即代码、可 diff 图表 | 语法紧凑、自动布局、适合技术文档 | 不承诺像素级排版和高级定制视觉；不接管泛化“画一个图” |

通用图类型可以重叠，但触发接口必须以“输出媒介”区分。只有 `svg-generator` 保留泛化的展示型画图入口；另外两个 skill 使用明确媒介关键词触发。

### 1.3 验收标准

- **AC-01（REQ-01）：** 三个 skill 都显式经过各自目录内的 `DiagramPlan`，并在输出前执行本目录内的可运行校验。
- **AC-02（REQ-02）：** 用一组路由测试验证普通“画图”、明确 SVG、明确 Draw.io、明确 Mermaid 四类请求不会误路由或多路由。
- **AC-03（REQ-03）：** 每个 skill 文件夹内部只有一套本地规范来源，主文件只描述接口和执行流程；文件夹外不存在运行时引用、共享目录、符号链接或生成时依赖。
- **AC-04（REQ-04）：** 三个 skill 各自保存独立的主题标记文件，但标记名称、版本号、文字层级、间距阶梯和语义连线值保持兼容；一致性通过仓库审查验证，不通过共享文件实现。
- **AC-05（REQ-05）：** 五类架构图各有一个模板、至少一个高质量示例和一组渲染快照验收。
- **AC-06（REQ-06）：** 基准输出满足：无越界、无重叠、无穿线、普通正文不小于 12px、对比度符合 WCAG、画布利用率目标 60%-80%、硬范围 50%-85%。
- **AC-07（REQ-06）：** 所有示例、模板和引用路径都存在；模板与示例不得以完全相同 blob 冒充不同语义类型。

### 1.4 当前审查证据摘要

- Draw.io：16 个 examples、15 个 templates 均通过现有 `validate_drawio.py --fail-on-warning` 和 `check_contrast.py --fail-on-warning`。
- Draw.io 模板存在 7 组完全相同 blob，其中包括：
  - `article-summary` 与 `card-summary` 完全相同；
  - `milestone-board` 与 `roadmap-timeline` 完全相同；
  - `business-layered` 与 `knowledge-map` 完全相同；
  - `comparison-vs` 与 `swot` 完全相同。
- SVG：`style-guide.md` 引用了 6 个已不存在的旧文件名；`SKILL.md` 仍要求输出到已不存在的 `img-output/`。
- SVG：多个示例使用大量 7-10px 文本，例如 `flow-rd-lifecycle.svg` 有 92 个小于 10px 的文本，`timeline-rd.svg` 有 45 个小于 10px 的文本。
- SVG 实际渲染抽查发现：
  - `business-architecture.svg` 右侧和底部内容被裁切，存在明显越界；
  - 架构图之间存在纯色、渐变、阴影、彩虹分层等多套视觉语言；
  - 部分图留白显著，部分图信息密度过高；
  - 部分架构卡片仍以内联多行文字承载三级信息，视觉层级不稳定。
- SVG evals 只有 10 条自然语言期望，`files` 全为空，没有可执行断言、基准输出和渲染回归。
- Mermaid：声明支持 15 类图，examples 只覆盖 11 类；缺少 quadrant、xy、sankey、block 示例；没有可运行语法解析或渲染验证，也没有统一主题。

## 2. 当前实现与差距

### 2.1 全局问题

#### P0：接口重叠导致路由不稳定

三个 description 都包含流程图、时序图、ER 图等关键词；`svg-generator` 和 `mermaid-gen` 还包含“画图、做图、生成图表”等泛化触发词。调用方必须同时理解三个近似接口，属于浅模块，容易造成随机路由和能力重叠。

#### P0：三个独立模块缺少兼容的本地质量契约

SVG 与 Draw.io 名义上颜色接近，但各自目录内的规则仍然散落；Mermaid 完全未接入。相同概念在不同 skill 中出现多种字号、边框、圆角、阴影和配色。需要在三个文件夹内分别建立兼容、带版本号的本地质量契约，同时保持任一文件夹可独立使用。

#### P0：缺少完整渲染闭环

Draw.io 有源文件校验，但还没有像素级渲染检查；SVG 和 Mermaid 没有可执行校验。现有检查无法可靠发现文字裁切、视觉拥挤、线条穿越、截图缩放后的可读性等问题。

#### P1：模板、示例、输出样例职责混淆

模板应是可复用骨架，示例应是完成品，output 应是生成结果。当前多个模板与示例完全相同，甚至不同意图模板完全相同，导致模板映射名义上丰富、实际结构没有区分。

### 2.2 `svg-generator` 审查

#### 当前存在的问题

1. **P0 输出路径失效：** 主文件仍指向 `img-output/`，当前仓库实际使用 `output/`。
2. **P0 示例存在硬质量问题：** `business-architecture.svg` 渲染后越界裁切；这说明仅检查 XML 可解析不足以保证视觉正确。
3. **P0 文字可读性不稳定：** 多个示例大量使用 7-10px 字号，与“文字清晰、专业”的目标冲突。
4. **P0 视觉语言漂移：** 同一架构类别混用高饱和纯色、渐变、重阴影、浅色卡片和彩虹分层；高级感没有统一定义。
5. **P1 规则重复且冲突：** `SKILL.md` 与 `assets/style-guide.md` 重复配色、箭头和布局；指南中又存在曲线/虚线回退示例，与“禁止曲线、虚线仅异步、错误红色实线”冲突。
6. **P1 引用失效：** 风格指南引用旧文件名，说明重命名后没有引用完整性检查。
7. **P1 缺少模板层：** 只有 examples，没有按意图选择的稳定模板，模型容易从任意示例抄取局部风格。
8. **P1 eval 不可执行：** 没有结构断言、渲染快照或失败阈值。
9. **P2 无障碍和兼容性不足：** 未统一要求 `<title>`、`<desc>`、字体 fallback、文本换行策略和 marker 引用完整性。

#### 可优化方向

- 把 SVG 定位为“高质量静态矢量渲染适配器”。
- 采用统一 `DiagramPlan` 和架构构图原型，不再直接从自然语言拼坐标。
- 新增模板、结构校验器和渲染快照测试。
- 把视觉“高级感”量化为克制配色、清晰层级、稳定间距、较少装饰和足够字号。

#### 具体优化建议

1. 新增 `templates/architecture/`，分别提供业务、应用、技术、部署、系统上下文模板。
2. 架构图默认使用中性背景 + 单一主色 + 不超过 3 个语义强调色；禁止整图彩虹分层。
3. 普通正文最小 12px，辅助文字最小 11px，卡片标题 14-16px，区域标题 18px，页面标题 24-28px。
4. 新增 `validate_svg.py`：检查 XML、viewBox、width/height、唯一 id、marker 引用、颜色标记、最小字号、文本/元素边界、明显重叠和画布利用率。
5. 新增渲染检查：统一渲染到 PNG，在 100% 和缩略图尺寸检查裁切、重叠和可读性。
6. 将 eval 改为“输入 + 使用模板 + 结构断言 + 视觉断言 + 基准文件”，先覆盖五类架构图和三类流程图。
7. 修复全部失效引用和输出目录；示例命名统一为“类别-主题-模式.svg”。

### 2.3 `xml-diagram` 审查

#### 当前存在的问题

1. **P0 DSL 只有文档约定：** 已设计中间结构，但没有实际 schema/validator；模型可以跳过而不被发现。
2. **P0 校验器存在盲区：** 当前未完整检查最小间距、区域标题安全区、字体下限、文字溢出、边缘交叉、连线穿越、端点距离和错误线颜色。
3. **P1 模板语义失真：** 多个不同类型模板是完全相同文件，模板名称与真实骨架不匹配。
4. **P1 模板与示例重复：** 示例不能证明基于模板产生了业务化变化，也增加维护成本。
5. **P1 能力描述有隐含冲突：** AGENTS 级规则强调错误分支和异步线，但当前 skill 把流程限制为“少分支、禁止复杂回环”；复杂流程是否支持没有明确决策。
6. **P1 对比度阈值偏低：** 默认 3.0 适合大字或标题，不能保证普通正文达到 4.5。
7. **P1 自动通过不等于视觉高级：** 校验器更擅长结构合法性，尚未验证渲染后的视觉质感和缩放可读性。
8. **P2 仓库包含已跟踪 `__pycache__`：** 二进制缓存不应作为 skill 资产维护。

#### 可优化方向

- 保留现有深模块优势，进一步让 DSL 成为真实接口，让校验器成为真实测试表面。
- 重新建立模板与示例的语义分工。
- 对架构图增加密度、网格、视觉重量和层次的专项校验。

#### 具体优化建议

1. 将 `dsl-schema.md` 收敛为可验证的 `diagram-plan.schema.json` 或明确 YAML schema，并提供 `validate_plan.py`。
2. 强化 `validate_drawio.py`：
   - 父子容器感知的最小间距与重叠；
   - 标题安全区；
   - 普通文本最小字号；
   - 正交边交叉/穿节点检测；
   - 连线语义颜色和虚实线检查；
   - 文本长度与卡片尺寸的溢出风险；
   - 边距和画布利用率分开计算，而不是只计算外接矩形面积。
3. `check_contrast.py` 按文字大小使用 4.5/3.0 双阈值。
4. 为五类架构图重做真正不同的模板；`knowledge-map`、`SWOT`、`milestone-board` 等不得继续复用无关 blob。
5. examples 只保留能体现模板业务化变化的完成品；模板中使用中性占位内容。
6. 明确流程边界：推荐支持“简约步骤流程”和“结构化复杂流程”两个子类型；复杂流程必须使用专门模板和更严格连线规划，不能由简约模板硬扩展。
7. 删除跟踪的 Python 缓存，并通过 `.gitignore` 防止再次进入版本库。

### 2.4 `mermaid-gen` 审查

#### 当前存在的问题

1. **P0 路由范围过宽：** description 使用“生成图表、画一个图”等泛化触发词，与 SVG/Draw.io 冲突。
2. **P0 无可执行验证：** 仅靠人工 checklist，不能证明 Mermaid 语法能被当前 renderer 解析。
3. **P1 类型覆盖不完整：** 声明 15 类，examples 只覆盖 11 类。
4. **P1 无主题约束：** 没有统一 theme、fontFamily、颜色角色、节点间距和文本换行配置，渲染结果依赖环境默认值。
5. **P1 缺少复杂度预算：** 没有限制节点数、标签长度、子图层级和方向选择，容易生成不可读的大图。
6. **P1 语法参考过浅：** 新型图表只有一句格式说明，缺少版本兼容、保留字、转义和中文标签策略。
7. **P2 示例格式不统一：** 有的包含标题和说明，有的只有代码块；无法作为稳定 few-shot 样例。

#### 可优化方向

- 将 Mermaid 定位为“Markdown/文档即代码图表适配器”。
- 用 `mermaid-gen` 目录内自有的 DiagramPlan 约束语义，但接受 Mermaid 自动布局的能力边界。
- 添加固定主题、复杂度预算和可运行语法验证。

#### 具体优化建议

1. description 仅保留 Mermaid、Markdown 图表、文档即代码等明确触发词。
2. 统一输出 `%%{init: ...}%%` 主题配置，字体、背景、主色来自 `mermaid-gen` 自有的视觉标记文件，并与另外两个 skill 的标记语义保持兼容。
3. 补充 quadrant、xy、sankey、block 示例，并给每类示例统一标题、适用场景、代码和说明。
4. 增加验证脚本：抽取 Markdown 中的 Mermaid fence；优先调用 `mmdc` 渲染，未安装时至少执行结构检查并明确降级状态。
5. 设定复杂度预算：默认节点不超过 20、subgraph 不超过 4 层、单标签不超过 24 个中英文字符；超出时拆图或降级为表格。
6. 明确视觉边界：Mermaid 不承诺像素级高级排版；用户强调“高级、品牌化、精确布局”时应路由到 SVG。

## 3. 目标方案与对比

### 3.1 目标模块结构

三个 skill 必须是三个完全独立、自包含的深模块。禁止新增共享目录；禁止运行时读取其他 skill 的文件；禁止使用符号链接、子模块或“先生成共享文件再使用”的隐式依赖。

```text
.opencode/skills/
  svg-generator/
    SKILL.md
    assets/
      routing.md
      diagram-plan.schema.json
      visual-tokens.md
      quality-contract.md
      architecture-system.md
      style-guide.md
    templates/
    examples/
    scripts/
    evals/

  xml-diagram/
    SKILL.md
    assets/
      routing.md
      diagram-plan.schema.json
      visual-tokens.md
      quality-contract.md
      architecture-system.md
      ...现有媒介规则
    templates/
    examples/
    scripts/

  mermaid-gen/
    SKILL.md
    assets/
      routing.md
      diagram-plan.schema.json
      visual-tokens.md
      quality-contract.md
      architecture-system.md
    references/
    examples/
    scripts/
```

每个 skill 文件夹独立暴露自己的小接口：

1. 本地 `DiagramPlan`：图类型、媒介、主题、密度、区域、节点、边、图例和约束；
2. 本地 `QualityContract`：字号、对比度、间距、边距、画布利用率、连线和渲染验收；
3. 本地 renderer 规则、模板、示例、脚本和 eval。

三个模块使用相同的标记命名和 `designSystemVersion`，但文件分别存在于各自目录。视觉一致性通过值兼容和回归对照保证，不形成跨目录依赖。删除另外两个 skill 后，剩余 skill 的文档引用、模板选择、生成和校验必须仍然完整工作。

### 3.2 统一生成流程

```text
当前：自然语言 -> 各 skill 自行理解 -> 直接生成 -> 不同程度人工检查

目标：自然语言
   -> 本 skill 的媒介路由判断
   -> 本地 DiagramPlan
   -> 本地图类型模板/构图原型
   -> 本地 renderer
   -> 本地结构校验
   -> 本地渲染校验
   -> 本地质量契约判定
   -> 交付
```

### 3.3 高级架构图视觉系统

#### 构图原型

| 架构类型 | 默认构图 | 必要语义 |
| --- | --- | --- |
| 业务架构 | 场景层 → 能力层 → 对象/资源层 | 角色/场景、能力域、业务对象、治理 |
| 应用架构 | 左入口 → 中核心 → 右外部；核心区上下分服务/数据 | 入口、网关、核心应用、数据、外部依赖、观测 |
| 技术架构 | 自上而下分层 + 左右侧跨切能力 | 协议、运行时、中间件、数据、安全、监控 |
| 部署架构 | 区域 → 网络 → 子网 → 集群 → 节点嵌套 | 网络边界、实例、存储、流量、容灾、监控 |
| 系统上下文 | 中心系统 + 周边角色/系统 + 明确关系 | 系统边界、角色、上下游、协议/关系 |

#### 视觉基线

- 12 列或等价网格；区域、卡片、标签分别使用稳定的间距阶梯。
- 页面标题 24-28px；区域标题 18px；卡片标题 14-16px；正文 12-14px；辅助文字不小于 11px。
- 浅色背景使用暖白/冷灰，不使用纯白大底；深色背景不使用阴影。
- 默认只有一个品牌主色；状态色只用于真实语义，不用颜色装饰每一层。
- 同级组件相同圆角、边框和视觉重量；禁止随机渐变和大面积高饱和色块。
- 内容先充实再布局；稀疏时优先补足语义或缩小画布，禁止用大容器撑满。
- 复杂关系优先调整分区，不依靠穿越多层的长箭头。

### 3.4 优先级排序

### 6.3 风险与缓解

- **高风险：路由收紧造成旧触发词失效。** 先建立路由回归集，再修改 description；保留迁移说明。
- **高风险：统一主题让现有示例风格大幅变化。** 以五类架构基准先行，其他示例分批迁移，不做一次性全量重绘。
- **中风险：严格校验出现大量历史失败。** 新规则先以 warning 运行，基准样例清零后再升级为 error。
- **中风险：三套本地契约长期发生漂移。** 三个目录使用相同 `designSystemVersion`、字段命名和验收用例；每次调整视觉基线时必须分别更新并运行三个 skill 的本地验证，但不得引入共享文件或生成依赖。
- **中风险：Mermaid renderer 不可用。** 校验器显式区分结构验证与渲染验证，CI 中固定 renderer 版本。
- **低风险：模板重构误删有价值示例。** 删除前做引用扫描、内容 hash 和渲染对照，先替代后删除。

```powershell
git revert <该阶段提交哈希>
```
